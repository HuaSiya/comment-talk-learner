# B站 + 贴吧学说话 / Comment Talk Learner

让麦麦每天从 **B站评论区** 和 **百度贴吧楼层** 学一点真人说话的方式：句式、语气、反问、自嘲、接话习惯，而不是学具体的梗。学到的内容写入麦麦原生的 **表达方式库**（`expressions` 表，`session_id=NULL` 即全局表达），由现有的表达选择机制在聊天时自然使用。

> 和 `B站学梗`/`贴吧学梗` 的区别：那两个插件学“一个梗是什么意思”，写入黑话库；本插件学“人怎么说话”，写入表达方式库。

## 功能

- 每天定时（默认北京时间 04:30，带随机抖动）自动跑一轮。
- **B站来源**：全站热门、分区排行、关键词搜索、指定 UP、固定 BV。
- **贴吧来源**：指定吧、可选关键词过滤；只有回复数超过下限、且过滤后有效楼层达到目标的帖子才计数，不足会跳过并继续找下一个。
- **B站评论质量过滤**：默认剔除公式化套话、玩梗、捧场、打卡、标题党、广告/引流、辱骂/隐私、AI 元讨论和 AI/Bot 摘要评论；纯反应按 8% 少量保留，近似复读去重，并按“个人经历/细节/观点”质量分优先取样。
- **AI/Bot 识别**：参考常见 B站过滤器的思路，组合已知账号名、等级、默认头像、签名、用户名关键词，以及“主人汇报/视频摘要/建议清单/评价/角色自称”模板家族和“首先/其次/最后”等结构骨架打分。
- 只取评论/楼层，清洗掉 @、链接、表情码、广告/引流、纯语气词。
- 未登录时 B站 热门评论列表通常只返回 3 条，所以默认同时抓取楼中楼（每条热门评论最多 20 条回复），既补足样本，也更接近“人怎么接话”。
- 用模型抽取“情境 + 说话方式”，要求给出原文证据 id，并核对引号里的原话。
- 可选二次复核：过滤不可复用、脱离原视频/原帖听不懂、冒犯/引战/广告的内容。
- 与现有表达库做模糊去重，默认每天最多新增 8 条、累计最多 800 条。
- 支持手动触发、预览、状态、库查看和管理员回滚。

## 安装

- 插件市场搜索 **B站+贴吧学说话**，或插件 ID `github.husiya.comment-talk-learner`
- 手动安装：把仓库目录放到 `MaiBot/plugins/comment-talk-learner/`，重启 MaiBot
- 配置：复制 `config.example.toml` 为 `config.toml`，或在 WebUI 插件配置页修改

重启后日志出现 `B站+贴吧学说话插件已加载` 即成功。

> `config.toml` 留在本地，不要提交到仓库；升级插件时保留它。

## 命令

| 命令 | 说明 |
|---|---|
| `/学说话` | 立即跑一轮并自动入库（后台执行，完成后回包） |
| `/学说话预览` | 跑一轮但不写库，只回候选，适合先看效果 |
| `/学说话状态` | 今日运行、下次时间、配额、累计导入、最近错误 |
| `/学说话库` | 查看本插件最近导入的表达 |
| `/学说话回滚 确认` | 仅 `admin_users` 可用，删除本插件导入且未被人工改过的记录 |

建议第一次先用 `/学说话预览` 观察 1–2 轮，再开自动入库。

## 配置

`config.toml` 可以在 WebUI 的插件配置页改，也可以直接编辑后重启 core。

公共设置（`[plugin]`）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `write_to_db` | `true` | `false` = 只预览，不写表达库 |

| `run_on_start_if_missed` | `true` | 启动时已过点且今天没成功，是否补跑 |
| `max_expressions_per_day` | `8` | 每天最多新增表达（跨轮累计）；可填任意正整数，0 表示不限制；额度用完时提前跳过 |
| `max_total_imported` | `800` | 本插件累计导入上限 |
| `min_confidence` | `0.6` | 抽取置信度门槛 |
| `review_enabled` | `true` | 二次复核 |
| `review_min_score` | `0.65` | 复核分数门槛 |
| `llm_task` | `learner` | 复用麦麦已有的模型任务（下拉选择 learner/utils/planner 等） |
| `llm_fallback_task` | `utils` | 主任务输出为空/坏 JSON 时换任务重试 |
| `llm_batch_size` | `40` | 每次模型分析多少条评论/楼层 |
| `llm_timeout_seconds` | `180` | 单次模型调用超时；避免被 RPC 默认 30 秒超时打断 |
| `seen_video_ttl_days` | `14` | 同一视频/帖子多少天内不重复取样 |
| `max_retries_per_day` | `2` | 每天失败后最多重试几次 |
| `retry_interval_minutes` | `30` | 失败后隔多久重试 |
| `command_cooldown_seconds` | `300` | 手动命令冷却秒数 |
| `banned_words` | `[]` | 额外屏蔽词 |
| `admin_users` | `[]` | 允许回滚的用户 ID；留空禁用回滚 |

B站来源（`[sources]`）：

```toml
[sources]
popular_enabled = true
popular_pages = 1
zone_rids = []       # 游戏=4，动画=1，生活=160，知识=36，科技=188，鬼畜=119，美食=211
keywords = []        # 例如 ["大学生日常", "职场"]
up_uids = []         # 指定 UP 主 UID
bvids = []           # 固定补充 BV 号
per_source_limit = 5      # 每个指定来源最多几个候选；热门会多取一些补位
max_video_age_days = 30

max_videos_per_run = 6    # 每轮最多保留几个“达标视频”；不足会继续找下一个
max_comments_per_video = 40 # 过滤后每视频至少要有多少条有效评论；不足则跳过该视频
include_sub_replies = true
sub_reply_roots = 3
sub_replies_per_root = 20
min_reply_count = 50      # 视频评论数必须 >50 才取样（即 51 条及以上）
min_comment_chars = 4
max_comment_chars = 120
formulaic_filter = true   # 严格过滤公式化/玩梗/捧场/标题党/无意义评论
reaction_keep_ratio = 0.08 # 纯反应（草/笑死/666）保留比例，0=全丢
ai_bot_threshold = 60     # AI/Bot 风险分达到多少就丢弃
rate_limit_seconds = 1.5
request_timeout = 20.0
max_request_retries = 2
sessdata = ""
```

来源合并是轮转的：指定 BV/UP/关键词/分区优先各取少量，再用热门补足，避免全站热门把指定来源挤掉。

达标视频的计数规则：

- `min_reply_count = 50` 表示视频总评论数必须 **大于 50**（51 条及以上）才进入候选；正好 50 条会被跳过。
- `max_comments_per_video = 40` 是 **过滤后的有效评论数**：清洗、去重、公式化/AI/广告等过滤后，至少保留 40 条才算 1 个达标视频；不足 40 条的视频会被跳过，不占视频名额。
- `max_videos_per_run = 6` 统计的是 **达标视频数**，不是尝试过的视频数；某个视频不足 40 条时会继续处理下一个候选，直到凑够 6 个或候选池耗尽。
- 热门列表会自动多取一些候选作为补位池；如果候选池耗尽，本轮达标视频可能少于上限，`/学说话状态` 和汇总里会给出提示。

### B站评论质量过滤

评论进入模型前会经过四层：

**1. 基础硬过滤（始终开启）**

- 空/纯表情、纯 @、长度不符、中文占比低于 50%、纯数字/乱码、重复字符。
- 广告/引流：URL、QQ/微信/手机号/邮箱、加V、私信、领券、返利、兼职、刷单、代练、看主页、带货、优惠券等。
- 辱骂/隐私：人肉、开盒、身份证、住址、裸照、严重辱骂等。
- AI 元讨论：我是AI、作为AI、人工智能、机器人、人机、大肥鱼、本鱼、本鲸、DeepSeek 等。
- 视频元信息：第X、来了、打卡、前排、沙发、热乎等。

**2. 公式化/玩梗（`formulaic_filter = true`）**

- **抢前排/玩梗**：火钳刘明、火前留名、惨案、打破惨案、空耳、计数君、下次一定、意满离、爷青回、泪目、能者先阅、前排打卡、热乎的。
- **捧场/追更**：宝藏 UP、关注了、百大、这么高质量为什么没人看、你火了、看好你、期待下一期、哇 UP 好厉害、这才是 XX 该有的样子、建议反复观看、收藏了。
- **固定句式**：听君一席话胜似一席话、但凡有一点意义、一分钟等于六十秒、热评密码、中国有句老话、在？为什么你能发语音、前方高能、讲个鬼故事看进度条、禁止套娃、这么可爱一定是男孩子、失踪人口回归、诈尸了。
- **模板/标题党**：有没有一种可能、很难不怀疑、有没有大佬讲讲原理、这个 BGM 绝了、循环预定、耳朵怀孕、卡点舒服、耗时 X 年、爆肝 XX 天、逐帧分析、冒死上传、价值百万、内部员工泄露、不要笑挑战、人类迷惑行为大赏、99% 的人都做错了、颠覆三观、智商税。
- **特定梗/人物**：回答我/Look in my eyes/Tell me why、鸣潮公式/秧式新文、全民制作人、小米型/蔚来型、说点大家不想的、孙笑川 258，以及常见 B站梗词。
- **无意义**：纯数字、纯标点、复读、整条只有“好看/支持/加油/收藏了/学到了”等捧场词。

**3. AI/Bot 识别（`formulaic_filter = true`）**

- 已知的总结/课代表类账号名，以及用户名里的 `AI/GPT/Bot/助手/课代表/总结/摘要/小助理/字幕组` 等模式。
- 账号特征：Lv0–2、默认头像（`noface`）、无签名、用户名含 鲸鱼/肥鱼/本鱼/本鲸/大肥鱼；大会员会降分。
- 文本模板家族：主人汇报、视频摘要、建议清单、评价、角色自称；命中多个家族加分。
- 结构骨架：首先/其次/最后、1./2./3.、综上所述、总体来说、亮点/不足、适合人群、希望对你有帮助。
- 风险分 = 账号分 + 文本分，默认 **60 分及以上丢弃**；可用 `ai_bot_threshold` 调低/调高。
- 同一轮里被判定为 Bot 的用户，后面视频/楼层的评论也会直接跳过（跨页面前科）。

**4. 纯反应采样（`reaction_keep_ratio = 0.08`）**

草/笑死/awsl/666/太强了/好耶这类纯反应不全部删，按 8% 稳定采样保留，避免语料变成客服话术；设为 `0` 可全部丢弃。

另外：

- **质量分排序**：有个人经历、具体细节、明确观点、自然口语标记的评论优先喂给模型；模板化、复述视频、纯反应、空泛赞美降分。
- **近似复读去重**：同一轮里相似度 ≥ 0.86 的评论只保留第一条，避免“国道上设宴=国宴”这类复读刷屏。
- **链式过滤**：主评论因公式化、广告、AI/Bot 等原因被丢弃时，它下面的楼中楼回复也一并丢弃，避免在垃圾评论下面继续取样。
- 模型抽出候选后还会再校验一次：如果 style 引用的是公式化原话、style 在描述“评论区/前排/热评/玩梗”等平台行为，或所有证据都是公式化评论，也会丢弃。

> 如果某些正常评论被误伤，可以把 `formulaic_filter` 设为 `false` 对比一轮；关闭后仍保留长度、中文占比、广告/引流、辱骂/隐私、AI 元讨论和纯语气词等基础过滤。候选表达层面的公式化校验始终开启。B站来源日志和 `/学说话` 汇总里会出现“B站质量过滤 N 条（公式化/广告/AI/纯反应/复读等）”。

贴吧来源：

```toml
[tieba]
enabled = true
quality_filter = true        # 过滤公式化/玩梗/广告/AI/无意义楼层
bars = ["生活吧"]            # 会自动补“吧”
max_bars = 10                # 每轮最多处理前几个吧；超出的忽略
keywords = []                # 可选：只读标题/摘要包含这些词的帖子
scan_pages = 2               # 每个吧扫前几页帖子列表
max_threads = 0              # 达标帖子总数；0=每吧达标帖子数 × 吧数
threads_per_bar = 2          # 每个吧最多保留几个达标帖子
thread_pages = 1             # 每帖至少翻几页楼层；系统会按目标自动加 1-2 页缓冲
min_replies = 50             # 帖子回复数必须 >50（51 条及以上）
max_posts_per_thread = 30    # 过滤后每帖至少保留多少条有效楼层；建议比回复数下限低 5-10 层
min_post_chars = 6
max_post_chars = 300
include_op = false           # 默认只学回复楼层，不学楼主首楼
exclude_title = "水楼|签到|吧规|公告|广告|交易|招聘|投诉|申精|回复"
rate_limit_seconds = 2.0
cookie = ""                  # 贴吧 Cookie（BAIDUID/BDUSS/STOKEN），移动网页通道需要
proxy = ""                   # 数据中心 IP 被风控时，可填 HTTP 代理
transport = "auto"           # auto=客户端失败自动切移动网页；client；web
```

> 默认用“生活吧”是为了学日常接话；弱智吧、孙吧这类偏梗的吧容易抽出吧内黑话，插件会过滤“术语/黑话/梗/代指”类候选，但仍建议按你们群的氛围选吧。

贴吧达标帖子规则：

- `min_replies = 50` 表示帖子总回复数必须 **大于 50**（51 条及以上）才进入候选。
- `max_posts_per_thread = 30` 是 **过滤后的有效楼层数**：清洗、去重、公式化/AI/广告等过滤后，至少保留 30 条才算 1 个达标帖子；不足 30 条的帖子会被跳过，不占帖子名额。**目标不要设得和 `min_replies` 一样高**：帖子总回复数刚过下限时，扣掉楼主、广告和公式化楼层，未必能凑够目标；建议目标比下限低 5-10 层（例如下限 50、目标 30 属于偏严格但可用）。
- `threads_per_bar` 统计的是 **每个吧的达标帖子数**，不是尝试过的帖子数；某个帖子楼层不足时会继续看同吧的下一个候选。
- `max_threads` 是 **达标帖子总数**；`0` 表示由 `threads_per_bar × 吧数` 决定。当前 8 个吧 × 4 = 目标 32 个达标帖子，请求量很大，建议用 `max_threads` 限制。
- `thread_pages` 是每帖至少翻几页；系统会按 `max_posts_per_thread` 自动多翻 1-2 页作为过滤损耗的缓冲。
- 候选池耗尽时，本轮达标帖子会少于目标，不会拿不足 30 层的帖子凑数。

### 贴吧特有过滤

贴吧和 B站评论不太一样，除了共用的公式化/AI/广告规则，贴吧额外补充：

- **水楼/经验**：十五字、凑够十五字、水经验、经验+3、盖楼、抢楼、占楼、前排、沙发、板凳、地板、地下室、下水道、围观、路过、打酱油、留名、马克、make、mark、帮顶、顶帖、回复可见、下载留名。
- **感谢/顶帖模板**：楼主好人、一生平安、1024、感谢分享、谢谢楼主、楼主辛苦了、支持一下、学习了、收藏了、先马后看、马住、码住、留个脚印。
- **互粉/引流**：求粉、互粉、互关、已粉、回粉、眼熟我、混脸熟、看头像、看主页、加群、群号、群文件、资源君、网盘、提取码、解压密码、留邮箱、发邮箱、求资源、求链接、求种、种子、磁力、ed2k、迅雷、百度云、阿里云盘、夸克网盘、天翼云盘。
- **交易/招聘/代练**：出售/收购/求购 + 账号/资源/价格、闲鱼/转转/微店、代购/微商、兼职/刷单/日结/底薪/提成/包吃住、代练/代打/代肝/代抽/代充、刷好评/刷赞/刷粉/刷等级、网赚/副业/收徒。
- **Bot 用户名模式**：资源君、分享君、搬运工、自动回复、机器人、代练、代购、微商、刷单、兼职、广告、推广、交流群、QQ群、群主、管理员、官方客服、小编、吧务。
- **旧贴吧跟风梗**：不明觉厉、喜大普奔、人艰不拆、细思恐极、男默女泪、十动然拒、累觉不爱、图样图森破、元芳你怎么看、高端大气上档次、然并卵等。

贴吧网页楼层经常拿不到等级/头像/签名，所以贴吧的 Bot 判定只按“用户名模式 + 模板/关键词”打分，不会因为缺少等级信息误判；B站评论才使用等级、默认头像、签名等账号特征。

参考的过滤思路（都只做本地只读判断，不删帖、不举报）：

- `hanFengSan/TiebaCleaner`：广告标签、用户黑名单、楼层广告。
- `zhujiu1207/TiebaTS`：广告模板键、关键词过滤、用户 ID 过滤。
- `8qwe24657913/RefreshingTieba`：ABP 广告资源/模块清单。
- `eight04/tieba-keyword-filter`：默认广告关键词（`jiaoyimao.com/goods`、`广告`）。
- `LanluZ/Tieba-Purification`、`Erichestein0702/tieba-enhancer`、`luo-712-luo/tieba`、`pingantie/tieba-new-ui-blocker-with-blacklist.user`：网页广告选择器、用户自定义关键词/黑名单。
- 这些项目大多把词表留给用户自定义，没有公开稳定的“贴吧 Bot 名单”；本插件用“用户名模式 + 模板规则 + 关键词”组合补足。

读取量提醒：

- 10 个吧 × 2 个达标帖子 × 每帖 2 页 ≈ 40 页楼层请求，按 2 秒限速约 80 秒以上，再加模型抽取/复核。
- 想控制耗时就把 `threads_per_bar` 调到 1，或用 `max_threads` 设总量目标。
- **内容风险**：孙笑川吧、抗压背锅吧、核战避难所吧、2ch 吧等偏攻击性/成人/边缘内容。插件会丢弃 `taboo=strong`、公式化和“术语/黑话”候选，但仍建议先用 `/学说话预览` 看一轮，不合适就把这些吧从 `bars` 移除。

### 贴吧访问方式（重要）

这台服务器实测：

- `c.tieba.baidu.com` 客户端 JSON 接口返回 `110001`（风控），没 Cookie 时 `tieba.baidu.com` 网页返回 `HTTP 403`。
- **带 Cookie 的移动网页版 `tieba.baidu.com/mo/q/m` 正常**，能拿到吧帖列表和楼层。
- 所以 `transport="auto"` 会先试客户端接口，遇到 `110001/403` 自动切移动网页；`transport="web"` 可强制只走网页。

需要准备一个贴吧 Cookie（`BAIDUID`/`BDUSS`/`STOKEN`），建议小号。没有 Cookie 或代理时，贴吧来源会记录警告并跳过，B站来源仍然正常工作。

用调试脚本可以先测通不通：

```bash
python tools/dry_run_tieba.py \
  --bar 生活吧 --pages 1 --threads 1 --posts 10
```

## 注意事项与边界

- **B站风控**：默认 1.5 秒限速、单轮少量请求；遇到 `-352`/HTTP 412 会停止本轮并留待下次。`sessdata` 可选，不保证长期稳定；不要用主号。
- **贴吧风控**：数据中心 IP 常见 `110001`/HTTP 403；需要贴吧 Cookie 或代理，详见上面的“贴吧访问限制”。贴吧失败不会影响 B站来源。
- **贴吧达标帖子不足**：日志出现“有效楼层 18/30，跳过”时，增加 `thread_pages`、降低 `max_posts_per_thread`，或减少 `threads_per_bar`/`max_threads`。候选池耗尽时不会拿不足目标的帖子凑数。
- **自动入库会污染语气**：靠每日配额、二次复核、证据校验、公式化评论过滤、AI/Bot 识别、纯反应采样、模糊去重、敏感度过滤和回滚兜底。仍建议先用 `/学说话预览` 观察几天。配额是“每天跨轮累计”，手动补跑不会突破当日上限。
- **AI/Bot 判定会受账号信息影响**：B站评论会读取等级、头像、签名、用户名和会员状态；贴吧楼层没有这些信息，只按文本模板打分。
- **广告/隐私/AI 元讨论是硬过滤**：不随 `formulaic_filter` 关闭；如果正常讨论 AI 的评论被误伤，只能等后续把规则拆细。
- **B站样本变少**：如果开启 `formulaic_filter` 后可用评论太少，先用 `/学说话预览` 看过滤统计；确认是误伤再把 `formulaic_filter=false` 对比一轮，或调低 `min_reply_count`、增加 `max_videos_per_run`、提高 `reaction_keep_ratio`、提高 `ai_bot_threshold`（调高 = 放宽 Bot 判定）。
- **达标视频不足**：如果日志出现“有效评论 32/40，跳过并补下一个”，说明该视频过滤后不够目标条数。可以降低 `max_comments_per_video`、增加 `sub_reply_roots`/`sub_replies_per_root`，或减少过滤强度。候选池耗尽时本轮视频数会少于 `max_videos_per_run`，不会拿不足 40 条的视频凑数。
- **热评偏差**：热评偏梗和情绪表达，不完全是日常说话；用关键词/分区/UP 补充日常样本。
- **表达生效是概率性的**：新表达进入全局库后由原生选择机制抽取，不保证下一句立刻使用。
- **人工审核标记**：写入的是 `checked=False`。如果以后开启 `[expression] expression_checked_only = true`，这些记录不会被使用，除非在 WebUI 里人工审核。
- **向量索引**：直接写库不会立刻更新表达向量索引；如果开启 `use_vector_expression`，宿主的历史回填任务会后续索引，不影响本轮入库。
- **回滚**：只会删除 `daily_state.json` 中记录、且 style/situation 仍与快照一致的记录；人工改过或非本插件创建的记录不会动。
- **状态文件**：位于插件的 `ctx.paths.data_dir/daily_state.json`，请保留；删除会丢失“已看视频/已导入”记录，可能重复学习。
- 插件不读取视频画面，也不保证模型抽取完整或准确；它是“学习素材”，不是事实来源。

## 排错

- **命令没反应**：确认 `enabled=true`，并重启 core；中文命令需要 `/` 前缀。
- **一直失败**：看日志里的 B站错误；`-352` 等几分钟或调大 `rate_limit_seconds`；关键词/UP 来源失败可能只是 WBI 接口临时风控，热门仍可用。
- **`cap.call 超时 (30000ms)` / 模型没有返回任何有效候选**：插件已用 `llm_timeout_seconds=180` 覆盖 RPC 默认 30 秒。如果仍失败，调大 `llm_timeout_seconds`、把 `llm_batch_size` 降到 20、选更快的 `llm_task`（如 `utils`/`fast_model`），或减少 `threads_per_bar`/`max_threads` 缩短单轮耗时。
- **学不到东西**：热门视频评论数可能低于 `min_reply_count`，或候选都被公式化过滤/复核/去重过滤；用 `/学说话预览` 看是哪一步。
- **还在学“火钳刘明/下次一定”**：先确认 `formulaic_filter=true` 且已重启 core；如果模型仍从长评论里抽出固定说法，看日志里的“引用的是公式化评论”原因，必要时在 `banned_words` 里补词。
- **表达太奇怪**：先把 `write_to_db=false` 或 `daily_enabled=false`，用预览观察；必要时用 `/学说话回滚 确认`（先配置 `admin_users`）清掉本插件记录，再调低 `max_expressions_per_day` 或提高 `min_confidence`。
- **想只学某个圈子**：把 `popular_enabled=false`，配置 `zone_rids`/`keywords`/`up_uids`/`bvids`。
